# Trusted job coordinator

This process holds the coordinator database and Redis credentials. It bridges committed outbox IDs to BullMQ, verifies each queue envelope against persisted job intent, claims durable work, and groups signed application authentication failures into stable account/IP incidents. Event effects and job completion share a transaction. It never runs customer code or calls provider write adapters.

Assign up to five organizations through `GOTCHU_ORGANIZATION_IDS` for the private pilot. Runtime configuration requires `GOTCHU_COORDINATOR_DATABASE_URL` and `GOTCHU_REDIS_URL`; each database login belongs only to `gotchu_coordinator`. Empty assignment stays explicitly unready. `/health/live` and `/health/ready` use port 3003 by default.

Optional `GOTCHU_WORKER_URL` and `GOTCHU_RUN_CAPABILITY_PRIVATE_KEY` enable signed, scoped calls to the separate investigation process. HTTPS is required outside explicit loopback development/test. Without this configuration, investigation jobs and runs record unavailable states while deterministic processing continues. The trusted gateway enforces durable read counts and checkpoint authorization. Model calls stay disabled until the provider adapter enforces authoritative per-run token/spend accounting. The agent never receives these database, Redis, or signing credentials.

The initial detector is five failures per ten-minute account or IP window; these are fixture defaults awaiting representative-traffic calibration. Processing caps a queried window at ten thousand events and records degradation instead of pretending the window was fully inspected. Other detectors, customer notification delivery, scanner profiles, and provider write adapters remain release gates. Unconfigured adapters fail visibly. Capacity and latency targets are not established by a successful unit test.

Postgres remains the delivery authority after Redis loss or retry exhaustion. Reconciliation recreates eligible transport records, while investigations with unsettled provider reservations require reconciliation rather than another model call. A terminal scoped checkpoint can complete a recovered job even after its original run deadline, provided the current job lease is valid and no reservation remains. Run and job finalization share one transaction.

Recovery selects up to 100 eligible jobs per lane, visiting deterministic work first. An investigation backlog cannot consume the entire event-recovery batch.

BullMQ uses `gotchu-deterministic-v1` with one worker slot, `gotchu-investigations-v1` with two slots, and `gotchu-assessments-v1` with one slot per coordinator. Slow assessment and investigation calls cannot consume the deterministic slot or its recovery batch. Both outbox publication and reconciliation route by job kind through `createCoordinatorTransport`; unsupported adapters still fail explicitly. Shutdown stops dispatch, drains workers, and closes all queues and owned Redis clients before the database.

Inject `assessmentRunner?: AssessmentRunner` in `CoordinatorDependencies`; its method is `run(input: AssessmentRunInput): Promise<AssessmentReport>`. The input comes from `backend.assessments.getRequest` under the current durable job lease, not from Redis payload or caller URL/path. The adapter resolves an operator target key and must perform only read-only, bounded checks, with all I/O settling within 60 seconds. Reads run outside a database transaction. `backend.assessments.recordResult({ input, leaseToken, report })` validates and commits report plus job atomically. Successful jobs expose `reportId`; missing adapters, invalid output and failed/overlong checks record explicit failure reasons without a report. Stale leases never finalize or reset another consumer's claim.

The watchdog stops waiting after 60 seconds. An adapter operation that ignores its I/O deadlines retains its in-process slot until it settles; later attempts fail `assessment_runner_busy` rather than accumulating background operations. This watchdog is not process isolation or forced cancellation. No customer code, hosted model or provider write runs through this port. Without `assessmentRunner`, audit jobs retain `audit_adapter_not_configured`. The real controlled engine is wired separately in the process entry point; its constructor is not imported by this port.

`pnpm --filter @gotchu/coordinator test:live` creates disposable Postgres and Redis containers, runs role/persistence-backed delivery checks, and removes only those containers. These tests use synthetic report evidence and a blocked test adapter to verify lane isolation and lease fencing. They do not prove the real engine's source/HTTP checks. `pnpm --filter @gotchu/database test:postgres` separately exercises real report storage, tenant/role denial, idempotency conflicts, stale-completion rollback, output binding, repeatable demo seed and concurrent demo admission. Build packages before running these commands.

When upgrading from the shared `gotchu-jobs-v1` queue or a coordinator that routed audits through the deterministic queue, stop the old coordinator before starting this version. Postgres reconciliation republishes unfinished jobs into their new lane, including already-delivered outbox intent, once any current durable lease expires. Old Redis records are not executable authority. These slot limits are per coordinator process, not a measured throughput or latency guarantee.

New events reject year-zero timestamps. Older incompatible timestamps remain stored but are excluded from detector windows using a guarded PostgreSQL conversion; coverage stays degraded while those rows remain. Aggregation serializes each application's window reads and writes to prevent an older snapshot from reducing incident counts.

Customer version-2 assessments use `customerAssessmentRunner` and `backend.customers`. Unknown scanner/transport failures and reclaimed customer claims become `assessment_reconciliation_required`; they are not automatically rescanned. This also keeps target renewal/revocation blocked after a failed job, because a timeout or lost connection does not prove remote work stopped. An operator must establish scanner quiescence before reconciling that durable quarantine. No customer HTTP endpoint clears it. Other current-state/validation failures retain their explicit reason codes.
