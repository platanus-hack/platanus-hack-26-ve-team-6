# `@gotchu/validator`

Long-lived D05 worker. It claims durable validation rows through `gotchu.validation_claim`, loads the private base and candidate snapshots from Postgres, builds bounded tar inputs, and runs a configured fixed runner profile. Firecracker is the default; the explicit development Docker mode (`GOTCHU_VALIDATOR_EXECUTION_KIND=docker`) requires `GOTCHU_VALIDATION_DOCKER_IMAGE_SHA256` and supports only the offline selected-test profile. Docker is not VM-class isolation or an automatic fallback. It binds to loopback only and keeps a quarantined run's lease/capacity until an operator reconciles its state or the process shuts down.

The worker needs a `gotchu_validator` runtime login and `GOTCHU_VALIDATOR_DATABASE_URL`. Its Ed25519 PKCS#8 key is created with mode 0600 at `~/.config/gotchu/validator/ed25519.pem`; `GOTCHU_VALIDATOR_KEY_PATH` may select another path. Set `GOTCHU_VALIDATOR_RUNNER_CACHE_DIR` to an owner-only directory for the Firecracker images, sandbox self-test record, and per-job files; the worker, validation admission checks, and readiness gate use the same directory. When unset, the runner keeps using `~/.cache/gotchu-runner`. `GOTCHU_VALIDATOR_FORCE_GATE_CLOSED=1` is a local fail-closed exercise switch. Readiness and health listen on `127.0.0.1:4410` by default.

Each attestation is signed over canonical JSON from `validationAttestationPayloadSchema`. The verifier loads the registered public key by `keyId`, validates the schema, and verifies Ed25519 over the exact JSON payload. The public projection omits signatures and private snapshots; `getValidationFacts({organizationId, actionRef})` returns signed attestations for the independent action verifier.

Run the service in the same user systemd session used by the isolation self-test. Preserve its `XDG_RUNTIME_DIR` and `DBUS_SESSION_BUS_ADDRESS` when constructing a restricted service environment; an inaccessible user bus prevents scope creation and cleanup verification. The service also needs effective access to `/dev/kvm`. A cached successful self-test alone does not establish that a differently launched process has these privileges.

`node24-npm-test` executes `npm test`. The worker extracts functional counts from a bounded `test-results/*.json` artifact containing `{ "passed", "failed", "skipped" }`; a configured regression test must also report `regression: "failed_for_target" | "passed"` in that artifact or reproduction remains unavailable.

`node24-tsx-selected-v1` supports dependency validation with 1–20 explicitly selected existing Node/TS test files and an optional name pattern. It uses the pinned guest-owned loader/reporter and accepts only `test-results/gotchu-node-selected-v1.json`. Missing/incomplete results cannot pass. A failing or unavailable selected baseline stops the run before candidate execution. Signed evidence binds the suite ID/version, profile, exact selection/digest and baseline/candidate counts. Selected compatibility coverage does not establish exploit reproduction or a passing full suite. See [the runner profile](../../packages/runner/README.md#selected-node-compatibility-profile).

The test files and `package.json` scripts must match the base snapshot byte for byte. Both profiles require `scriptName: "test"`; arbitrary commands are unsupported. Source corrections retain their complete-rescan and reproduction gates. The explicit `dependency_rescan_v1` policy permits unknown static dependency reachability while requiring the selected inventory, advisory, license, core scanner and frozen package-artifact coverage; aggregate report coverage remains partial. The verifier independently checks the signed scope and approved dependency change.

An Owner/Operator may retry a failed or inconclusive dependency validation with the same candidate and current suite configuration, at most five attempts per rolling 24 hours. Each retry preserves immutable history and advances the candidate's current-run pointer. Queued/running requests are deduplicated; quarantined work requires operator reconciliation before retry. No retry grants repository write access or exact PR approval.

`pnpm --filter @gotchu/validator test:vm` is opt-in (`GOTCHU_TEST_VM=1`) and requires the real Firecracker gate to be open. It honors `GOTCHU_VALIDATOR_RUNNER_CACHE_DIR` for both the gate check and VM runner when set. The checked-in fixture repositories are intended to exercise candidate regression behavior inside the actual VM.
